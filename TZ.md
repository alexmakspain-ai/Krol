# Техническое задание: Приложение учёта расходов (Expense Tracker)

## 1. Общее описание

Веб-приложение для учёта личных расходов с визуализацией по категориям,
таблицей операций, возможностью добавления расходов и экспортом данных.

## 2. Стек технологий

| Слой | Технология |
|---|---|
| Frontend | Angular + TypeScript |
| Backend | Python + FastAPI |
| ORM | SQLAlchemy + Alembic (миграции) |
| База данных | SQLite (файл, без отдельной настройки сервера) |
| Авторизация | JWT (простой логин/пароль), хэш пароля — passlib/bcrypt |
| Графики | Chart.js (через ng2-charts) |
| Экспорт | CSV/Excel — генерируются на backend (Python: csv-модуль, openpyxl) |

## 3. Функциональные требования

### 3.1 Авторизация
- Регистрация (email/имя пользователя + пароль)
- Вход / выход
- Данные каждого пользователя изолированы (расходы и категории привязаны к user_id)
- Пароли хранятся в БД в хэшированном виде (passlib/bcrypt)
- После входа — JWT-токен для доступа к API

### 3.2 Виджет 1 — Круговая диаграмма расходов
- Тип диаграммы — кольцевая (donut), в центре — название и сумма выбранной
  /топ категории (при наведении/клике на сегмент — обновляется)
- Отображает расходы за выбранный период, сгруппированные по категориям.
  Свой независимый фильтр периода (не связан с таблицей/списком)
- Выбор периода: текущий месяц (по умолчанию), произвольный диапазон дат,
  быстрые пресеты (неделя / месяц / год)
- При наведении/клике на сегмент — сумма и процент по категории в центре
- Легенда со списком категорий (цветной маркер + название) под диаграммой

### 3.3 Виджет 2 — Таблица расходов
Это отдельный, независимый от диаграммы виджет со своим собственным
фильтром периода (см. референс: диаграмма показывает "THIS MONTH", список
записей — "THIS YEAR", у каждого виджета свой выбор периода).

- Колонки: Название расхода, Категория, Сумма, Дата
- Сортировка по каждой колонке
- Свой независимый фильтр по периоду (не связан с диаграммой)
- Пагинация (если записей много)
- Возможность удалить/редактировать запись
- Каждая категория — с цветной иконкой (как в референсе), для визуального
  соответствия цветам на диаграмме

### 3.4 Виджет 3 — Добавление расхода
- Форма: Название, Сумма, Дата (по умолчанию — сегодня), Категория
- Категория: выбор из существующего списка (select) ИЛИ создание новой
  категории прямо из формы
- Валидация: сумма > 0, название и категория обязательны
- После добавления — таблица и диаграмма обновляются без перезагрузки страницы

### 3.5 Экспорт данных
- Кнопка экспорта в CSV
- Кнопка экспорта в Excel (.xlsx)
- Экспортируются данные с учётом текущего примененного фильтра по периоду
- Формат колонок в экспорте совпадает с таблицей расходов

## 4. Модель данных

Детали уточним по ходу разработки. Черновая схема на старте:

**User**
- id
- email
- password_hash
- created_at

**Category** (категория расходов)
- id
- user_id (ссылка на User)
- name
- color (для диаграммы)

**Expense** (расход)
- id
- user_id (ссылка на User)
- category_id (ссылка на Category)
- title (название расхода)
- amount (сумма)
- date (дата)
- created_at

Блок-схема связей — см. отдельный файл `data-model.mermaid`.

## 5. Нефункциональные требования

- Адаптивный дизайн (desktop в приоритете, мобильная версия — минимально рабочая)
- Время отклика UI при добавлении расхода — без перезагрузки страницы (SPA)
- Код структурирован для дальнейшего расширения (легко добавить новые виджеты)

## 6. Вне рамок текущей версии (не делаем сейчас)

- Мультивалютность
- Совместные/семейные бюджеты
- Уведомления и бюджетные лимиты
- Мобильное приложение (нативное)

## 7. Этапы реализации (высокоуровнево)

1. Инициализация проекта (backend + frontend), настройка структуры
2. Backend: модели данных, авторизация, CRUD для категорий и расходов
3. Frontend: страница логина/регистрации
4. Frontend: таблица расходов + форма добавления
5. Frontend: круговая диаграмма с фильтром по периоду
6. Экспорт в CSV/Excel
7. Полировка UI, тестирование сценариев
